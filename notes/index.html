第 1 轮 · 把网页正式发布到网上（2026-09-17）

我的需求 前两版都是存在电脑里、双击才能打开的网页，只能自己看。我想要一个能直接发链接给同学、老师和未来导师的网址，手机上也能正常打开。

AI 的交付

  • 网页托管到 GitHub Pages —— 免费静态托管、自带 HTTPS，不需要买服务器和域名。
  • 新建代码仓库 Bryanhw/bryanhw.github.io，线上地址 https://bryanhw.github.io/。
  • 补上浏览器标签页图标（favicon：蓝底圆角白字「B」）与作者信息、页面描述等 meta。
  • 补上 .nojekyll 与 README.md，确保 Pages 能正确构建。

过程中的坑

  • 本机的 github.com:443 HTTPS 传输间歇性被阻断，普通 git push 会失败。最终改为走 SSH，并把端口换成 443（在 ~/.ssh/config 里把 HostName 指向 ssh.github.com、Port 443），推送通道才稳定下来。
  • GitHub Pages 构建有 30~60 秒延迟，「推上去了」不等于「线上已更新」。为避免自欺，验证一律用 SHA256 字节级比对，确认线上拿到的确实是本地那一份。

第 2 轮 · 深色 / 浅色主题一键切换

我的需求 晚上看这个页面太亮了，希望能切换成深色；而且要记住我的选择，下次打开还是上次那个主题，不要每次都重新点。

AI 的交付

  • 右上角新增主题切换按钮，浅色（蓝白）↔ 深色（深夜蓝）。
  • 所有颜色统一改用 CSS 变量定义在 :root，深色模式通过 :root[data-theme="dark"] 整体覆盖 —— 切换主题不用改任何一处样式代码。
  • 访客的选择存在浏览器本地（localStorage，键名 yhw-theme），下次自动沿用。
  • 第一次访问、还没手动选过时，自动跟随电脑或手机的深色模式设置。
  • <head> 内置一段内联脚本，在页面渲染前就确定主题，避免「先白闪一下再变黑」。
  • 手机上连浏览器地址栏颜色也会跟着变（theme-color meta 动态更新）。

第 3 轮 · 做留言板（第一版：转发到我的邮箱）

我的需求 首页只有我的信息，别人看完没法跟我说点什么。我想加一个留言入口，让访客能留个话给我。

AI 的交付

  • 首页顶部新增「✍️ 给我留言」按钮，点进去是留言表单，也可以用网址 #/feedback 直达。
  • 表单 4 项：昵称（最多 24 字）、与我的关系（朋友 / 同学 / 家人 / 老师 / 其他，选「其他」才出现补充输入框）、正在使用的设备（手机 / 平板 / 电脑 / 其他，按访客当前设备自动预选）、留言内容（最多 300 字，右下角实时字数提示）。
  • 提交通道用 FormSubmit 把留言转发到我的邮箱，并保留 mailto: 作为最后兜底（三级：FormSubmit → 打开邮件客户端）。
  • 加上防重复提交与提交结果提示。

过程中的坑

  • 最早的方案只有 mailto: 链接。实测发现：mailto: 能不能用，完全取决于访客电脑装没装邮件软件、有没有配好账号 —— 本机就出现「邮件窗口弹出来了，但里面是空的」，访客以为提交成功，我这边却什么都收不到。所以改成了以服务端转发为主、mailto: 只做最后兜底。

第 4 轮 · 换成我自己的数据库

我的需求 留言只变成我邮箱里的一封邮件，留不住、没法统计、也没法管理；而且完全依赖第三方的免费转发服务，总觉得不踏实。我想让留言真正存进我自己的地方。

AI 的交付

  • 接入 Supabase（免费版 PostgreSQL 数据库），新建数据表 messages：昵称、关系、访问设备、留言内容、提交时间（服务器时间，访客无法伪造），以及一个仅给我自己参考的标记列 approved。
  • 数据库层面写死三条规则，而不是靠前端自觉：
    1. 匿名访客只能新增留言；
    2. 新增时只能标为「未审核」（即使有人改前端代码也没用，数据库会直接拒绝）；
    3. 匿名访客完全读不到留言内容。
  • 网页源码里只放一把可公开的 publishable key（它从设计上就是给公开网页用的）；真正的管理者密钥 service_role 绝不进网页。
  • 为了保持「单文件、零依赖」的设计，没有引入官方 JS 库，直接用浏览器原生 fetch 调用接口。
  • 三级兜底保留：数据库 → 邮箱转发（FormSubmit） → 打开邮件客户端，前一级失败才用下一级。

第 5 轮 · 公开留言墙 → 改为只站主可见 + 显示真实留言总数

我的需求 一开始我设想的是把留言审核后公开展示在页面上（留言墙）。后来觉得不行：访客留言时默认是「说给我一个人听」，公开出去未必是他们想要的；而且公开内容一旦出现不合适的话，我还得盯着删。所以留言墙不要了，只有我能看。但是 —— 一条都不显示的话，页面会显得没人来过，我希望访客能知道这里确实有人在留言，所以想显示一个真实的留言条数。

AI 的交付

  • 移除留言墙相关的前端代码（loadWall() / wallCard() / formatWallTime() / 刷新按钮等全部删除，静态校验确认这些标识符出现次数为 0）。
  • 数据库新增函数 message_count()：security definer + stable，只返回一个数字，访客拿不到任何一条留言内容。
  • 留言页新增 loadCount()：进入留言页才去请求这个数字（首页不产生该请求，避免浪费）。
  • 一条留言都没有时显示：「还没有收到留言，欢迎你做第一个。」；有留言时显示「已收到 N 条留言」（N 加粗）。
  • 万一数据库连不上、或返回的东西不是数字，这一行安静地隐藏，绝不在页面上弹报错。
  • 读取权限整体撤销，只单独放开「读总数」这一个函数 —— 防垃圾留言从「靠审核」变成「根本读不到」。

第 6 轮 · 新留言自动邮件提醒

我的需求 留言虽然存住了，但我总不能天天登录后台去看有没有新留言。有留言就主动告诉我。

AI 的交付

  • 在数据库内部装一个能发网络请求的扩展（pg_net），在 messages 表上挂触发器：每写进一行，就异步发一封提醒邮件到 yhw20070910@outlook.com。
  • 邮件标题形如 [个人主页新留言] 昵称（关系），正文是一张表格：昵称、关系、访问设备、留言全文、提交时间。
  • 整个提醒过程不含任何前端代码，因此前端不需要放任何额外密钥。
  • 提醒是异步的：邮件服务万一出问题，不会影响留言本身的保存，留言一定存得住。
  • 即使访客提交完立刻关掉页面，邮件照样会发出。

过程中的坑

  • 创建 pg_net 时按常规写法指定 schema 会报 schema "net" does not exist —— 原因是 pg_net 自己会创建名为 net 的命名空间，而「指定存放 schema」的语法要求该 schema 事先存在。正确写法是把它装到已存在的 extensions schema 下，装完仍然用 net.http_post 调用。

第 7 轮 · 提交前自查 + 清理测试数据 + 修正历史文档 + 线上核验

我的需求 这份网页是作业，要交出去了。我希望：文件干净（不要夹带脚本、临时文件、密钥）、数据干净（开发时我自己发的测试留言不要留在数据库里）、文档准确（前面几版文档里已经改过的文件名、文件夹名别再是错的），而且这些都要有据可查，不能靠「我觉得应该没问题」。

AI 的交付

① 提交前自查（全部通过）

  • 确认页面真正单文件自包含：外部 URL 0 个、相对路径引用 0 个、file:// 0 个。
  • 扫描密钥：没有数据库密码、连接串、私钥、service_role、sb_secret_ —— 那 3 处「命中」经人工核对，都是「绝对不要把 service_role key 放进去」这类警示注释的误报。
  • 确认页面不泄露任何访客留言内容；确认历史文档保留不删（只修正错的引用）。
  • 确认工作区仓库 git remote -v 为空，不可能被误推。

② 静态校验（check_v3.py） 35 个 id 全唯一、28 个 getElementById 目标全部存在、括号平衡、46 个 CSS 变量全部有定义、字数上限 maxlength 与常量 FB_OPINION_MAX 一致；留言墙遗留标识符 0 处。结果：ALL STATIC CHECKS PASSED。

③ 数据库测试数据归零 开发期间留下的测试留言（最后一条是我自己发的 333333）与误建的空表全部清理。收尾核验：匿名调用 message_count() 返回 0，匿名读取留言返回空。

④ 修正历史文档里的失效引用 前面几版的文档里提到了后来已改名的文件与文件夹，逐处修正（工作区版与桌面存档版都改）：开发对话记录.md → v1开发记录.md、文件夹名 cst ai 智能网页作业 → cst ai 个人主页作业、文件名自指错误等。历史文档保留不删，只把错的引用改对。

⑤ 线上核验 用无头浏览器抓取线上 #/feedback 页面的 DOM，确认留言计数那一行实际渲染为「还没有收到留言，欢迎你做第一个。」，并且对访客可见。 线上文件与本地存档、工作区三方 SHA256 完全一致：612A8FDA…C2FE3，75582 字节。

过程中的坑（值得记下来）

  • Supabase SQL Editor 的结果面板只显示最后一条语句的结果。 多条语句一起跑，前面语句的明细会被盖住；要单独看某条，得在编辑器里选中那一段再按 Ctrl+Enter。
  • 结果面板可能是上一次查询的残留。 面板显示「1 row」并不代表我刚跑的那条语句真的执行了 —— 我用 delete 删了两次都没生效，最后是去 Dashboard → Table Editor 里勾选那行删掉的（表格变成「No rows found」这种看得见的反馈最可靠）。
  • 教训：判断一次写入是否生效，必须以独立的只读查询返回值为准，不能依赖「我点了 Run / 看到 Success」。
  • 排查过程中还顺手排除了三个看似可疑、其实无关的原因：不是缓存（CF-Cache-Status: DYNAMIC）、不是项目搞错（页面与后台是同一个项目）、不是 RLS（rls_forced = false，且本就没有 DELETE 策略）。

第 9 轮 · 开场动画：五盏发车灯 → 赛车冲刺 → 结尾一行字（2026-09-18）

我的需求 希望打开网站时先来一段赛车主题的开场动画，有点仪式感，不要一进来就是干巴巴的信息页；但要保留「跳过」按钮，别让人干等。

AI 的交付（含一次改版）

  • 初版做的是「发车灯倒数 3-2-1 → 赛车冲刺 → 卡通车手挥方格旗」。
  • 看过之后我提出改版，最终定稿为： 五盏红灯铺满整屏、逐个点亮 → 五盏同时熄灭（这才是真实的 F1 发车信号）→ 赛车才登场冲刺 → 终点车手挥方格旗 → 定格一行字 It's all to drive for with Bryan，全程约 6.2 秒。
  • 灯、赛车、车手、方格旗、速度线全部是手写的 SVG + CSS，不是图片 —— 不增加任何外部依赖，放大也不模糊。
  • 手机上五盏灯自动改成竖排，同样铺满屏幕；电脑上保持横排（更接近真实 F1 发车灯）。
  • 沿用我此前的要求：车身不含任何文字或号码。
  • 点「跳过」、或系统开启了「减少动态效果」，都会不播放直接进主页。
  • 已于 2026-09-18 上线（提交 885b117）。

AI 是怎么保证「顺序对」的 动画顺序不能靠肉眼看截图来判断。AI 写了一个时序推演脚本 intro_timeline.py：从浏览器 CSSOM 里直接读出每个动画的延迟、时长、填充模式与关键帧，按 CSS 规则算出每一毫秒各元素的不透明度，再断言编排顺序。这个脚本第一次运行就抓到了两个真 bug（见下）。

过程中的坑

  • CSS 隐式 from 的陷阱（真 bug）：写 @keyframes fadeOut{to{opacity:0}} 时，隐式 from 取的是元素基础样式的值，而不是上一帧的值。如果基础值本来就是 0，整段动画就退化成 0 → 0 的空动画，元素会直接跳变而不是淡出。lightOff 与 speedOff 都中招了，修法是显式写出 from{opacity:1}。这个问题肉眼极难发现，是时序脚本抓出来的。
  • 虚拟时间不推进 CSS 动画时钟：无头浏览器的 --virtual-time-budget 只推进 setTimeout，CSS 动画的 currentTime 恒为 0。所以「第 3 秒画面长什么样」不能用它来判断，只能靠 CSSOM 推演 + 强制定格的截图探针。
  • GitHub 的 SSH 通道（443 端口）这次也时通时断，大约三次才能成功一次（失败串是 port 443: Connection timed out）。解决办法是把「提交」和「上传」解耦，只对上传做反复重试，避免留下「已提交但没推上去」的半成品状态。

第 10 轮 · 开场动画第三轮改版：赛车现代化 + 车头朝左 + 方向盘特写（2026-09-18）

我的需求 我找了两张参考图，提了三点要求：

  1. 赛车造型要更现代 —— 参考 FIA 2026 概念车渲染图：深蓝渐变车身 + 红/黄/白拉花、Halo 座舱保护结构、大轮毂罩、多层前翼、宽大尾翼。
  2. 车头方向调转 —— 原来车头是朝右冲的，改成整体镜像朝左，速度线方向也要跟着反过来。
  3. 新增一个方向盘特写镜头 —— 参考真实 F1 方向盘：碳纤维蝶形盘体、顶部换挡灯带、中间液晶屏显示挡位与数据、左右多功能按钮、握把指示灯。

AI 先问了我三个问题（这点很好）

  • 赛车方向怎么调？→ 我选了整体镜像，车头朝左（而不是只翻转车头）。
  • 方向盘插在哪一段？→ 我选了「灯灭之后、赛车冲刺之前」。
  • 方向盘屏幕上显示什么？→ 我选了显示挡位与数据。

AI 的交付

  • 赛车按「车头朝左」整张重画：前翼在最左、尾翼在最右，深蓝渐变车身 + 三色拉花 + Halo + 大轮毂罩 + 卡通车手；冲刺关键帧终点改为向左的 translateX(-232%)；速度线定位由 left 改成 right，飞行方向同步反向。
  • 新增方向盘特写：碳纤维斜纹底、顶部 10 颗换挡灯逐颗亮起（绿 4 / 黄 3 / 红 3）、中央屏幕显示挡位 8 与 LAP 88 / 56.0 / +1.250 及 4 组数据、左右按钮区（N/OV/FUEL/MIX/SCEN 与 PIT/OK/PL/SOC 等）、底部四色旋钮、两侧握把指示灯；盘面还会绕盘心微微打一下方向。
  • 因为多了方向盘这一段，总时长从 6.2 秒延长到 7.4 秒（给方向盘留出约 1.1 秒的可读时间，结尾保留约 1 秒定格）。
  • 已发布上线（提交 aded24f）。

AI 主动加的两条顺序硬约束

  • 方向盘必须在灯灭之后才出现；
  • 方向盘必须在赛车出现之前完全退场（否则赛车会穿过方向盘）。

这两条都写进了时序脚本做断言：实测方向盘 2.50s 出现、2.90s 全亮、4.00s 淡出，赛车 4.05s 才登场。

过程中的坑

  • 方向盘一开始没有居中（真 bug）。 居中位移 translate(-50%,-50%) 原本只写在动画关键帧里，于是「动画一旦被禁用」，盘面就贴在屏幕中心、右侧溢出屏幕。这是几何探针用 animation:none 定格元素时暴露出来的。教训：居中这类基础定位要写在元素的基础样式里，动画只负责在其之上叠加位移和缩放。
  • 校验脚本自己也有 bug。 时序脚本里嵌套函数用 global ok 只能改模块级变量，改不动 main() 里的局部变量，导致 FAIL 根本没计入退出码 —— 脚本报「通过」其实是假的。改用可变容器 state = {"ok": True} 才修好。这说明校验脚本本身也要被质疑。
  • 收尾检查的虚拟时间预算必须跟着总时长走。 总时长改成 7.4s 后，原来卡 8s 的收尾检查会失败（7.4s + 0.62s 收尾 ≈ 8.1s 才移除），已改成 9s。
