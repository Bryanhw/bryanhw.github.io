第 1 轮 · 定方向：v4 到底要做成什么样（2026-09-24）

我的需求

v3 已经上线并且功能齐全了，但我觉得它「能用了」和「好看、好用」之间还有距离。所以 v4 我不打算加功能，我要的是把现有的东西做精致——同样还是我这个人、同样还是蓝色科技感加赛车风，但每个细节都要更耐看。具体我想清楚四件事：

  • 核心目标：视觉 / 交互全面升级，不加新功能。
  • 风格方向：延续蓝色科技感 + 赛车风，做精致化，品牌识别不能丢。
  • 动效力度：适度增强就好，要滚动进场、悬停微动、按钮和卡片的反馈、平滑过渡；但要考虑看不惯动效的人，得能降级。
  • 代码起点：在 v3 上增量演进，不要推倒重写——我不想为了好看把已经验证过的功能弄坏。

还有一条是我自己定的：功能全保留。主题切换、数字分身「小文」、Supabase 留言、赛车开场动画、中英双语、6 个关注方向子页、对话记录页，一个都不能少、不能坏。

AI 的交付

AI 把我的要求落成了可执行的方案：

  • 先建一个 v4 基线：把 outputs/v3/index.html 逐字节复制成 outputs/v4/index.html。这样做的意义是——任何时候都能干净回退，v3 的线上版本原封不动躺在那里。
  • 把「精致化」限定在样式层：只动 CSS（设计令牌、组件样式），不碰 HTML 结构、不碰 JS 逻辑、不碰中英文案。因为结构一动，风险就不可控了。
  • 提出了分阶段推进的建议：先做「设计令牌 + 导航 + 全局组件 + 首页」，出浅色和深色的首页截图给我看；我认可之后再推广到其余视图。这样不至于等全部做完才发现方向不对。

我采纳了这个节奏。

第 2 轮 · 先做首页：设计令牌 + 导航 + 组件（2026-09-24）

我的需求

按上面定的节奏，第一刀只切「设计令牌 + 导航 + 全局组件 + 首页」，做完出截图给我验收。

AI 的交付

1）先把「设计令牌」这一层做扎实

AI 的解释是：与其在每个组件上单独调阴影和过渡，不如先把「一套尺子」定下来，后面所有组件都引用它。所以先改 :root：

  • 阴影从「一层」改成多层叠加（贴地细影 + 大范围柔影），说这样更接近真实光照，卡片才不会像浮在纸上的贴纸。
  • 新增了几个令牌：--ring-soft（统一的键盘焦点环）、--brand-grad（品牌渐变，所有主按钮的底色都从这里取）、--grad-text（文字渐变）、--glow-blue（品牌蓝光晕）、--ease（统一缓动曲线 cubic-bezier(.2,.7,.2,1)）。
  • 深色主题同步这一整套。其中文字渐变在深色下自动换成更亮的色阶，否则深色背景上的深蓝渐变字会看不清。
  • 顺手做了一次清理：中途加过 --hair / --edge / --plinth 三个令牌，后来发现用不上，又删掉了，避免留下「定义了但没人用」的死代码。

2）导航

玻璃质感加强（blur(16px) saturate(1.35)）；当前页的链接加了品牌渐变底色和顶部内高光；「联系我」「主题」「语言」「汉堡」几个按钮统一加了内高光、悬停轻微浮起和按下反馈。

顶部那条「速度条」还加了一道缓慢的斜向扫光（4.2 秒一轮），呼应赛车主题——但这个扫光在不希望有动效的系统设置下会自动停掉。

3）首页

Hero 卡片渐变加深、加顶部内高光；数据条上面加了一条品牌色「速度条」，数字改成品牌渐变文字，同时保留纯色回退（防止老浏览器上数字直接看不见）；分区标题「关于我 / 我关注的方向 / 获奖与荣誉」加了品牌色短横线。

4）意外发现：一个从 v3 就一直没生效的效果

这是这轮最有价值的发现，AI 主动报了上来：

页面上那些「斜切按钮」（联系我、认识我、给我留言、发送、提交留言等）都是用一个叫 clip-path 的 CSS 属性切出来的斜角。问题在于——clip-path 会把 box-shadow 一并裁掉。

也就是说，v3 里这些按钮的悬停阴影、以及「给我留言」按钮那个呼吸光晕（@keyframes leaveGlow），实际上从来就没有显示出来过。因为只是"少了一点阴影"，所以一直没人发现。

v4 把这类元素统一改成 filter: drop-shadow()——它作用在裁剪之后的轮廓上，因此会贴合斜角形状。那个呼吸光晕现在才真正可见。

5）验证

AI 说它没法直接"看"图（这个环境里它读不了图片内容），所以视觉结论只能靠程序化的像素体检，最终好不好看必须我自己拿眼睛判断。它跑了两件事：

  • 静态校验（check_v4.py）：结果 ALL STATIC CHECKS PASSED——47 个 id 全唯一、31 个 getElementById 目标全部存在、5 个代码块的括号在跳过注释和字符串之后完全平衡、51 个 CSS 变量全部有定义（没有悬空引用）、留言和反馈的关键接线完好、v3 遗留的留言墙标识符 0 处残留。
  • 本地截图体检（shoot_v4.py）：用无头 Edge 直接截本地文件，6 张图全部 OK，浅色首页和深色首页的亮度比 5.34 倍（确认主题确实区分开了）。

过程中的坑

  • 控制台中文乱码：脚本输出的中文在 PowerShell 里显示成乱码。一开始我以为是文件写坏了，后来确认只是控制台编码（GBK）问题，文件本身没问题。脚本里加 sys.stdout.reconfigure(encoding="utf-8") 能缓解。
  • 模型读不了图：AI 明确说了它无法读取图片内容。这点很重要——它给出的「渲染正常」是从像素统计推出来的（宽度、平均亮度、内容底部位置、品牌蓝像素数量），不是它"看到"了页面。观感判断必须由我来做。

第 3 轮 · 首页验收通过，推广到其余视图（2026-09-24）

我的需求

我看了浅色和深色的首页截图，通过，让它按同一套风格推广到其余视图。

AI 的交付

这次是把上一轮定下的那套「尺子」用到了所有剩下的页面：

  • 二级页骨架：个人信息卡片、特点卡片加了悬停时轻微浮起（2px）和阴影。
  • 6 个方向子页：小节图标加了投影；列表前面的圆点加了品牌蓝光晕。
  • 数字分身页：聊天头部加内高光，我发出去的气泡加了投影，快捷问题按钮悬停会浮起来，输入框统一焦点环，发送按钮改成品牌渐变 + 真实投影。
  • 留言反馈页：输入框和意见框的焦点环统一，单选胶囊选中态改成品牌渐变 + 内高光，提交按钮换成真实投影，提交成功的对勾图标加内高光。
  • 页脚：链接悬停的下划线加了偏移，颜色加深一点。
  • 版本号：v3.1 → v4.0。这里有个细节——一共 4 处要一起改：<head> 里的 <title>、页脚可见文字、以及中英文字典里的两个 key。字典的 key 必须和页面上的文本逐字一致，否则切到英文时这条就换不过去。所以是四处一起换的。
  • 触屏降级：新增了一条 @media (hover:none) 规则。原因是手机上没有真正的「悬停」这个概念，不加这条的话，手指点完按钮后那个"浮起"状态会卡住不退。现在在触屏设备上直接取消所有浮起反馈。

验证

  • 静态校验：ALL STATIC CHECKS PASSED（这次是 162183 字节 / 2909 行）。
  • 全站截图：13 张全部通过——首页（浅/深）、个人信息（浅/深）、我的特点、数字分身、留言反馈，以及 6 个方向子页。
  • 窄屏截图：3 张全部通过，宽度没有被强制缩放，说明顶栏在手机宽度下不溢出。

这里要记一个局限：无头 Edge 的最小窗口宽度约 492px，比这更窄会被强制放大，所以手机断点里「小于 430px」那一档（隐藏英文后缀、按钮收窄）没有被截图覆盖。这是 v3 阶段就确认过的老问题。

过程中的坑

  • PowerShell 不支持 heredoc：我让 AI 跑一段 python - <<'PY' ... PY 的临时脚本，结果 PowerShell 直接报语法错误。结论是：这个环境里临时脚本一律写成 .py 文件再执行，不要用管道/heredoc 传内联代码。
  • 自己写的检查脚本自己误报：AI 写了个定点检查脚本，把「斜切元素不允许有 box-shadow」当硬规则，结果把 v3 本来就有的 inset 内高光也判成了问题。后来把规则改成「允许 inset，禁止外投影」才对。教训是——检查脚本本身的规则也得审查，否则会追着假问题跑。

第 4 轮 · 存档同步与 v4 记录页（2026-09-24）

我的需求

v4 先不发布，我要自己在本地先看一遍。但桌面存档要更新：直接用 v4 覆盖存档里的主页，旧版给我留个备份。另外，v4 的对话记录页也要做出来。

AI 的交付

1）桌面存档同步（存档目录：桌面\cst ai 个人主页作业\）

  • 先把存档里现存的 v3 版主页备份成 index-v3.html.bak（155103 字节，SHA256 与原 v3 基线逐字节一致）；旧的记录页也一并备份成 notes-v3.html.bak（53744 字节）。

  • 每一步都做 SHA256 逐字节复核，全部通过。

2）v4 对话记录页

把本文档转成 outputs/v4/notes.html——单文件、零外部依赖、和主页共用同一套设计令牌和同一个主题键（yhw-theme），所以两个页面的深浅主题是互通的：在主页切了深色，进记录页也还是深色。

生成用 .deepworks\tmp\build_notes_v4.py（本文档是唯一内容源），产物 28800 字节 / 367 行 / SHA256 06F9A560…5914732C，20 项内置校验全部 PASS（标题与章节数、章节编号连续、4 个表格全部转换、代码段转义、无 Markdown 记号泄漏、版本号、主题令牌已定义且被引用、动效降级等）。

随后又给记录页做了截图体检：整页含页脚完整拍到（页面高 7440px）、品牌蓝像素 127653、浅色/深色亮度比 9.00×，ALL CHECKS PASSED。这 3 张记录页截图也同步进了存档。

3）关于发布

按我之前定的规矩（没我同意不许 push），v4 现在只在本地和桌面存档里，线上仍然是 v3.1。等我看完本地效果、点头之后才会发布，发布时还要做线上与本地 SHA256 逐字节比对来确认真的同步了。

过程中的坑

  • PowerShell 会把中文文件写坏：我图省事用 Get-Content / Set-Content 给脚本做字符串替换，结果 PowerShell 5.1 默认按 GBK 读 UTF-8，把中文写成了 U+E1ED 这类非法字符，Python 直接报 SyntaxError: invalid non-printable character。改文件必须用编辑工具，或用 Python 显式指定 encoding="utf-8"。
  • 自写的检查指标差点骗了自己：我给记录页加了一条"文字行占比不得低于 v3 基准"，结果 v4 是 0.346、v3 基准是 0.524，"失败"了。查下去才发现这个指标衡量的是"页面非不非空"，而两页源文体量差 2.6 倍（v3 有 13621 个可见字符，v4 只有 5189 个），本来就不该横向比。判断"渲染是否正常"要靠结构校验和"整页是否拍到页脚"，不是靠这个比例——指标要想清楚它到底在量什么。
  • 独立视觉模型的描述不能当真：过程中有个视觉模型帮忙看图，它把 v4 说成"暖色系、纸感风格"，还说"用 Playwright 做了验证"、页面上有"文章列表和文章详情页"——这些全都不存在。它只能用来粗判（有没有报错、浅深主题切没切），具体结论必须回到程序化校验和我自己的眼睛。

第 5 轮 · 数字分身「小文」扩面与去机械感（2026-09-24）

我的需求

访客留言里反复出现同一类反馈（分析见 outputs/feedback-analysis.md）：问不太到自己想知道的事，而答不上来的时候往往是一句「私聊我」，把话头直接堵死了。所以这一轮的目标就两条：能答的尽量答全，答不上的别再机械地甩联系方式。

AI 的交付

1）知识库扩容——新增 3 条事实，全部取自页面上本来就有的信息，一个字都没编：

新增字段内容
city城市：深圳
twin身份自述：我是数字分身、不是本人；不确定的事不编
site这个网站是怎么做出来的：单文件零依赖、留言存在 Supabase、另有一页对话记录

2）新增 4 条问答规则：身份自述、留言怎么留、住哪、网站本身。顺序上把「身份自述」排在名字规则之前，否则「你是……」会被名字那条抢答。

3）同义归一化：新增 SYNONYMS（12 组）+ normalize()，并把匹配改成两遍——第一遍按原文匹配，全部落空才归一化重试。这样只做加法，绝不会改变原本命中的回答（原来的答案不会因为这一轮改动而变差）。

4）兜底重写：答不上来时不再甩一句「私聊我」，而是坦白说答不上来 + 说清边界 + 给两种可以直接照抄的问法 + 一个能点的「留言反馈」链接（指向 #/feedback）。

5）快捷问题 8 条 → 10 条（新增「你住在哪？」「你是真人吗？」）。

6）打字停顿不再固定 550ms，改成随问题长度在 420–950ms 之间变化（短问快答、长问稍等），少一点机械感。

7）顺手修掉两个真 bug：

  • 一个从 v1 起就存在的显示 bug（线上 v3 也有）：联系方式和获奖两条回答里的换行，写成了字面 \n（反斜杠加 n）共 14 处；而聊天窗口是 white-space:pre-wrap，访客看到的就是一串反斜杠。这两条恰好是最需要排版的文本（三个邮箱、三个奖项）。已全部改成真正的换行。
  • 一个本轮自己引入的语义误答：「你有女朋友吗」被校园生活规则的「朋友」关键词命中，答成了校园生活。已加一条私人问题规则（不代答、也不编），排在校园规则之前。

过程中的坑

  • --dump-dom 会把标签里的 < > 转义成 &lt; &gt;：我断言"兜底里有可点链接"，第一轮直接失败——其实页面里链接是好的，是取数那一步把 & 转义了。断言含 HTML 的返回值前必须先反转义。这类"假故障"最危险的地方在于：如果当时顺手把链接改成纯文字来"修 bug"，就把真功能改坏了。（本轮新增结论）
  • 测试脚本自己写错了，却看起来像代码错了：3 个"英文提问"的断言用了英文标志词（digital twin / single-file / feedback page），但站点的设计是中文界面下用英文提问、回答仍是中文，所以必然落空。改成中文标志词后全过。教训：断言失败先怀疑断言。
  • 字面 \n 这个坑藏了四轮：它只出现在"三个邮箱 / 三个奖项"这两条回答里，正好是最需要排版的文本，而且线上 v3 也有同样的 14 处。教训是——光看截图不够，要把字符串转义扫一遍。
  • 测试自己会"污染"下一次测试：UI 实测里我点了语言按钮，语言被记进 localStorage；而浏览器 profile 目录是复用的，所以第二次跑的时候页面直接以英文启动，7 条中文断言集体失败。这跟代码一点关系都没有。修法是：每次跑用全新的 profile，并且开跑前先把语言归一到中文。修完连跑三次全过——只过一次的测试等于没测。（本轮新增结论）
  • 归一化判断写成严格相等，方向就反了：页面 lang 属性的实际值是 zh-CN，我按 === 'zh' 判断"现在是不是中文"，结论是"不是"，于是把中文切成了英文，断言全部反向失败。改成按前缀判断（indexOf('zh') === 0）才对。这类错误看起来完全像功能 bug，其实是断言写错了。（本轮新增结论）

过程中的坑

  • 自己写的探针报错，先怀疑探针：连续三次假故障（路由没对上、地址里的 # 被截断、响应头大小写），没有一次是页面真的坏了。当时要是直接去"修页面"，就会把好功能改坏。
  • --dump-dom 的虚拟时间不等真实网络：留言计数在那个模式下永远是隐藏的，看起来像功能坏了；换成真实时间的浏览器一看，正常显示 16 条。要测异步结果，就必须用真实时间的浏览器。
